# 2026-08-30

- 엔코더 실장착 + 배선 브링업. `firmware/encoder_wiring_check/` 진단 스케치를
  ESP32(`/dev/ttyUSB0`, esp32s3)에 플래시하고 바퀴를 손으로 돌려가며 4선 점검.
  - **1차**: 좌 B상(GPIO16)이 정지 상태에서 0 고착 → 사용자가 배선 수정.
  - **2차~3차**: 정지 중인데 4핀 레벨이 매 샘플 튀고 `edges`가 초당 수십씩
    누적 (유령 엣지). 외부 풀업/접촉 여러 번 손봐도 안 잡힘.
  - **원인**: 모터 EMI가 실드 안 된 엔코더 케이블로 유입. **케이블 실드를
    ESP32 GND에 접지하니 즉시 해결** — 정지 상태에서 8초간 4핀 레벨/edges 완전
    고정. (실드는 "필수 아님"이지만 이 차량에선 사실상 필수였음.)
  - 검증 통과: 좌우 분리 OK(한쪽 돌리면 그쪽 ticks만 변함), 단조 카운트 OK,
    손으로 1회전 ≈ 1383 ticks (스펙 360P/R x4 = 1440, 손돌림 오차 감안 정상).
  - **전진 부호**: 휠체어를 전진 방향으로 밀었을 때 처음엔 좌우 ticks가 반대
    부호로 움직임 → 좌측 엔코더 A/B(Black↔White, GPIO15/16) 물리적으로 교환 →
    이후 전진 시 좌우 둘 다 같은 방향(감소)으로 카운트. 헤더 5번 조건 충족.
  - 정지 상태에서 4핀이 전부 1(HIGH)일 필요는 없음 (디스크 정지 위치에 따라
    각 상이 0/1). wiring_check 헤더의 "정지 시 전부 1" 기준은 엔코더 미연결
    베이스라인 기준이라 실제 연결 후엔 안 맞음 — 진짜 판정은 손돌림 테스트.
- 배선 확정 후 `esp32_joystick_emulator.ino` (프로덕션) 재컴파일/재플래시.
  시리얼에서 `E,<lt>,<rt>` 스트림 ~50Hz 확인, 정지 시 ±1~2 tick 지터만.
  펌웨어 코드는 미변경 (2026-08-29 커밋 그대로).
- **부호 정규화 미적용**: 현재 배선 기준 전진 = tick '감소' (좌우 모두). 좌우
  트림 자동계산은 양쪽 부호만 일치하면 되므로 이대로 사용 가능. 나중에
  오도메트리 적분 작업 들어갈 때 펌웨어 디코딩을 `(b<<1)|a`로 양쪽 다 뒤집어
  전진 = tick 증가로 정규화할 것.
- 호스트 설정: `arduino-cli upload`가 `/dev/ttyUSB0` 권한 거부(Permission
  denied) → `inu`를 `dialout` 그룹에 추가(`usermod -aG dialout inu`). 다음
  로그인부터 영구 적용. 이번 세션은 `chmod a+rw`로 임시 처리 (재부팅/재연결 시
  사라짐).
